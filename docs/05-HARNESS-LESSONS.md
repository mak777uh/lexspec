# Agent harness lessons from a published 672/672 proof run

Why this file is in a repository about legal language: the closest public worked example of
"a model proposes, a machine disposes" at scale is not a legal project. It is an autonomous agent that
proved every Lean 4 theorem in PutnamBench — 672 problems — for a total of $111.85. The running conditions,
the stopping rule and the way defects were triaged are directly transferable to LexSpec's own pipeline, and
several of them are the reason our rules are worded the way they are.

Everything numeric below was read on 2026-10-28 from two primary sources: the repository
[`nearai/putnambench-deepseek`](https://github.com/nearai/putnambench-deepseek) and the benchmark's own
[leaderboard data](https://github.com/trishullab/PutnamBench/blob/main/docs/results.json). Where the two
disagree, both are quoted.

## 1. What was actually claimed, precisely

PutnamBench contains **1724 formalisations** in total: **672** in Lean 4, 640 in Isabelle, 412 in Coq
([benchmark README](https://github.com/trishullab/PutnamBench)). The run solved the **Lean 4 track**, not all
three. The leaderboard has two Lean variants, and the difference is not cosmetic:

| Track | Key in `results.json` | Leaderboard label |
|---|---|---|
| answer pre-filled | `lean-wsolution` | "Lean with answer — answer placeholders pre-filled (out of 672)" |
| answer withheld | `lean-nosolution` | "Lean no answer — answer placeholders not provided (out of 672)" |

346 of the 672 problems contain an answer placeholder that the prover must infer in the harder variant
(leaderboard notes, same page). The NEAR AI entry is on `lean-wsolution`. As of 2026-10-28, 43 methods report
on `lean-wsolution` and only 3 on `lean-nosolution` — where **Midas Prover** reports 672/672 at $6.17 and
31 min per problem (total $4,144.29, added 2026-09-12). The honest one-line summary of the state of the art is
therefore:

> 672/672 is no longer a frontier capability; it is a solved track. What moved is the price.

Price, on the same track and the same leaderboard:

| Method | Solved | Cost per problem | Total |
|---|---|---|---|
| Humanfia (GPT-5.6 sol) | 672 | mean $44.5 | ≈ $29,900 |
| Forall, Astrio (Claude Opus 5) | 672 | mean $3.52, median $2.49 | $2,364.39 actor-side |
| **NEAR AI (DeepSeek V4 Flash/Pro)** | **672** | **mean $0.17, median $0.04, max $11.18** | **$111.85** |
| Goedel-Architect | 642 | mean $5.8 | — |
| Midas Prover (no-answer track) | 672 | mean $6.17 | $4,144.29 |

Humanfia's entry predates NEAR AI's (2026-08-27 vs 2026-09-04), so the claim that matters is **cost**, not
priority: roughly 21× cheaper than the cheapest other with-answer solution per problem and 262× cheaper than
the GPT-5.6 run. The repository also prices the *same trajectories* as if they had been generated by other
models: $11,000 (GPT-5.5), $8,257 (Sol), $20,644 (Fable). Those ratios — 74× to 184× — are what the "100–200×
cheaper" claim in interviews actually rests on.

One more caveat that the leaderboard entry states and the headline does not: **two of the 672 solutions were
submitted against corrected formalisations**. That is section 3, and it is the most interesting part.

## 2. The stopping rule belongs to the harness

The agent gets a Lean file with a `sorry` and one tool: `bash`. It has exactly two ways to finish — a
`completed()` tool that runs the verifier, and a `disproved()` tool for the case where the statement itself
is false. If the model stops without either, the harness feeds it a nudge and continues.

Consequence, in the authors' words: one agent attempted to quit **3,423 times out of 5,106 turns** before
proving `putnam_2022_b6` (step 5,105, hour 26). The longest single run was `putnam_2021_a6` at 78 hours over
four attempts.

**Transferable rule.** "Done" must be a claim the *checker* makes, never the model. LexSpec states this as
§9 of the spec — the verdict ladder is computed, and a statement is never `CHECKED_ANCHORED` because its
author says so. The additional lesson is about *giving up*: a model that stops is not a model that failed, it
is a model that needs a nudge, and the nudge is safe only because the verifier — not the model — decides when
to stop.

## 3. Two formalisations were wrong, and only a prover found out

Both defects are in the benchmark's own upstream statements:

1. **`putnam_1974_b1`** — five points on a circle maximising pairwise distances. The official solution
   predicate ("some ordering has equal consecutive distances") is satisfied by degenerate configurations with
   repeated points, e.g. an equilateral triangle listed as `[A,B,C,A,B]`, which are not maximisers. The
   theorem as stated is **false**. The agent produced a machine-checked proof of `statement → False` with
   clean axioms; the fix adds `Function.Injective p`. This matches upstream issue #347.
2. **`putnam_2013_a5`** — area-definite lists, R² → R³. The statement pins 3D area to `μH[2]` on
   `Fin 3 → ℝ`, whose Pi instance carries the **sup metric**, so "area" is the plane-dependent
   Busemann–Hausdorff measure, not Euclidean area. The statement is provable but is not the informal problem.
   Fixed by moving to `EuclideanSpace ℝ (Fin 3)`, after which it was proved in ~5 hours.

Read that again as a fact about verification in general: **two out of 672 formalised statements were not
what they claimed to be, and no amount of proof-checking would ever have found it.** What found it was a
prover *failing*, followed by a human reading the failure as a claim about the statement rather than about
the prover. This is the exact failure mode LexSpec's L4 layer exists for, and it is the strongest empirical
argument in the repository for "anchor or refuse": the proof is only ever as good as the text it points at.

It also sharpens what a refusal means. A refusal is evidence about **the artifact**, and the artifact can be
the law, the corpus, or the encoding — not only the author's mistake. v0.1 has no channel for "the corpus
itself is defective". That gap is now a candidate for v0.2 (see [spec §11](10-SPEC-v0.1.md)).

## 4. Semantic re-validation, not a textual diff

The verifier checks four things: no `sorry`/`axiom`/`native_decide`, the theorem statement is byte-identical
to the frozen one, the file elaborates, and `#print axioms` is clean. Then a second check: the solved
theorem's fully-elaborated type (`pp.all`, clean environment) must be character-identical to the pristine
statement's.

Why the second check: a textual diff misses statement-rewriting exploits — notation, coercions and instance
resolution can make two different propositions print the same way. Comparing elaborated types compares what
the kernel actually saw.

**Transferable rule.** Identity must be checked on the *resolved* form, not the *spelling*. LexSpec's version
of this is §3 (canonical bytes, so identity does not depend on the editor) plus term resolution in `terms[]`
(so `поставщик` in an atom is the same object as `поставщик` in the definitions, not the same string). When
v0.2 grows a prover seam, this is the check it must inherit.

## 5. Cost is recorded per attempt, including failures

`costs.tsv` has one row per **agent run**: 724 attempts for 672 problems, with `solved = 0` rows retained.
The headline cost is a replay of those trajectories under a stated price list, not an estimate.

**Transferable rule.** `docs/20-METHOD.md` §6 requires a cost row per encoded clause, with `origin` naming
the model. The PutnamBench practice adds two fields worth copying: the number of *attempts* and the cost of
the failed ones. An encoding that took four attempts has a different economics from one that took one, and a
report that hides the failures will be quoted as if it were the median.

## 6. What we do not copy

1. **No unbounded run.** The harness had no turn or token budget, and one problem consumed 78 hours. LexSpec
   is a checker, not a search; a proposal pipeline around it must carry an explicit budget, because "no limit"
   is affordable only when the property is decidable by a kernel.
2. **No prover in v0.1.** A proof assistant buys nothing until the encoding is anchored and closed
   ([spec §11](10-SPEC-v0.1.md)). Adding Lean to a mis-anchored statement produces a true theorem about the
   wrong text — which is exactly section 3.
3. **No unverifiable claim.** The PutnamBench entry says its solution bundle was "shared privately for
   independent verification". That is legitimate for a competition benchmark, and it would be fatal here: an
   artifact a stranger cannot re-check is a claim, not a result ([README](../README.md)).

## 7. The uncomfortable detail

The repository's README states that its Python files and the README itself "were entirely written by Claude
Code", and that the agent's strategy instructions are "Claude Code-generated". The proving model was DeepSeek.
So the widely repeated framing — "Claude refuses, DeepSeek does the verification" — is, at least in this
project, not a division of labour between model families but a division between **writing the harness** and
**running it**. Both families did both kinds of work; the cost difference is real and the refusal difference
is a separate, narrower claim about security-flavoured requests.

Recording this matters for the same reason as everything else in this file: the useful question is not which
model is braver, it is which parts of the pipeline a machine can decide and which parts a human must.
