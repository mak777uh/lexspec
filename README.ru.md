# LexSpec

**Что это.** Спецификация, схема и эталонный проверяльщик для *юридических утверждений, которые может
проверить софт*: положение записывается как набор хохфельдовских правовых позиций, каждая привязана к
точному фрагменту закреплённой редакции правового текста, а программа решает, связен ли набор, все ли
привязки состоялись и какая доля утверждения действительно закрыта.

**Чем это не является.** Это не ИИ, который читает договор и говорит, что всё хорошо. Это не юридическая
консультация. Это не доказатель теоремы, не парсер статутов и не заявление о том, что прошедшее проверку
условие законно. Проверяльщик никогда не выводит слово «законно»; он выводит вердикт над тройкой
`(утверждение, кодировка, корпус@редакция)` и список того, что он не проверял.

Канонический текст — [README.md](README.md) (английский); при расхождении прав он.

## Одно правило

> **Привязка или отказ.** Атом без однозначного фрагмента (`span`) в закреплённой редакции — это не
> слабая проверка, это другой продукт. Фраза, которая встречается в тексте дважды, не привязывает ничего:
> такая ссылка после поправки молча переуказывает на другое место (`S2_SPAN_AMBIGUOUS`).

Всё остальное в репозитории следует из этого правила, включая те места, где инструмент отказывается от
работы, которую мог бы сделать.

## Почему четыре слоя разделены

«Формализовать юридический язык» — это четыре разные задачи, и их смешение и есть источник уверенной
бессмыслицы:

| Слой | Вопрос | Что есть здесь |
|---|---|---|
| **L1 Текст** | что именно сказано? | ничего: v0.1 не разбирает прозу. Человек или модель предлагает утверждение, и предложение можно опровергнуть |
| **L2 Модель** | какая это правовая позиция? | восемь позиций Хохфельда как закрытое множество, с коррелятами и противоположностями ([спец §4](docs/10-SPEC-v0.1.md)) |
| **L3 Вывод** | что следует и что противоречит? | только комбинаторные проверки: противоположности, пересечение сроков, объявленная политика конфликтов. Выводимости нет |
| **L4 Происхождение** | какие байты и какой редакции это говорят? | каждый атом привязан фрагментом + sha256 файла корпуса ([спец §5](docs/10-SPEC-v0.1.md)) |

Практическое следствие в L2/L3: позиции образуют два квадрата с известными противоположностями, поэтому
противоречия между ними **комбинаторны** — несколько сотен строк Python находят их без доказывателя.
«A не вправе делать X» рядом с «A вправе делать X» в одном документе — это не тонкая семантическая задача.

## Запуск

```bash
python tools/lexcheck.py examples/01-delivery-ok.lex.json          # человеческий вывод
python tools/lexcheck.py examples/01-delivery-ok.lex.json --json   # машинный отчёт
python tools/lexcheck.py --canonical examples/01-delivery-ok.lex.json  # канонический вид + sha256
python tests/run_tests.py                                          # сторожевой набор
python tools/lexspec_status.py                                     # цифры для раздела «Статус»
```

Python 3.11+, только стандартная библиотека. Ставить нечего.

Коды возврата: `0` — прошло, `1` — отказ, `2` — ошибка использования или разбора.

## Вердикты

Ровно три, по возрастанию силы. Формулировки — часть контракта:

| Вердикт | Что значит |
|---|---|
| `REFUSED` | утверждение не прошло проверку; у каждой причины есть код из закрытого словаря |
| `CHECKED` | закодированное связно и привязано там, где привязано, но хотя бы один атом открыт или покрытие ниже порога |
| `CHECKED_ANCHORED` | все атомы закрыты и привязаны; это по-прежнему **не** утверждение о праве |

Каждый отчёт дословно содержит:

```json
"not_claimed": ["legal validity",
                "completeness of the encoded law",
                "correctness of the corpus outside the pinned revision"]
```

Вердикт, процитированный без этого списка, — другое утверждение, чем сделал инструмент. Полный словарь
отказов — [docs/11-REFUSAL-CODES.md](docs/11-REFUSAL-CODES.md).

## Чего репозиторий не утверждает

- **Никакой юридической силы.** Вердикт — про кодировку, никогда про право.
- **Никакой полноты.** Покрытие — доля *утверждения*; 100 % покрытия неверно закодированного условия есть
  100 % покрытия неверной кодировки.
- **Никакого разбора статутов.** Ничто здесь не читает правовую прозу. Корпус — закреплённый фрагмент, и
  в его заголовке это написано.
- **Никакой выводимости.** «Закон требует X» не является выводом. «Атом `a1` привязан к ——— в этой
  редакции» — является.
- **Никакой стабильности.** v0.1 — черновик; коды и поля могут меняться, и отчёт всегда называет версию
  спеки, против которой проверялся.

## Статус

v0.1. Проверяльщик, схема, примеры и тесты существуют и запускаются; цифры в этом разделе производятся
командой `python tools/lexspec_status.py`, а прогон сторожевого набора лежит в `tools/SELFTEST.md` вместе
с командами и их настоящим выводом. Чего нет — перечислено в [спец §11](docs/10-SPEC-v0.1.md): без
выводимости, без преодолимости исключениями, без рассуждений между утверждениями, без семантики
юрисдикций, без подписанного сертификата.
